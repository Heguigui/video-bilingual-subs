# 流程

九步，其中三步是承重的、极易做错：时间轴、对齐、验收。

```
页面 ──► 媒体地址 ──► 字幕轨 ──► cue ──► 块 ──► 中文 ──► 双语 SRT ──► 烧录 ──► 验收
                        │                                        │
                        └── 去掉分段重叠                          └── 按句对齐，绝不在词内断行
```

## 1. 定位片源

播放器通常在页面标记里，一般是一个 playback id 或一条 `.m3u8`。Mux 的话 `https://stream.mux.com/<playbackId>.m3u8` 就是 master。有字幕时 master 里会带 `#EXT-X-MEDIA:TYPE=SUBTITLES`——整行留着，那就是时间轴。

## 2. 先时间轴，后翻译

`vtt_to_cues.py` 把字幕分段解析成 `[start, end, text]` 并去重。**HLS 分段本来就重叠**：第 *n* 段尾部的 cue 会在 *n+1* 段开头再出现一次。跳过去重，成片里每句话都会说两遍。

没有字幕轨的片源，先退到内嵌字幕流，再退到转写。转写不影响 5–7 步，时间轴的形状完全一样。

## 3. 视频

一条 `ffmpeg -i master.m3u8` 是单条 TCP 流，会卡死。技能改成枚举分段、十个并发进程抓取、再拼接。签名 URL 原样使用——重排参数会让签名失效。

拼完时长对不上，说明有分段缺失，不是下载完成。补齐后重新拼接。

## 4. 分块

原始 cue 只有 2–4 秒，而且断在句子中间。`build_blocks.py` 合并到句末，每块上限约 380 字符，再按约 3.8k 字符攒成翻译批次。

## 5. 翻译

由 agent 逐块完成，按 id 作键。规则在 `SKILL.md` 里，概括是：口语保持口语，自动字幕的胡话按意思修正，标识符原样保留，词表不许破。

## 6. 对齐

英文按句切；中文按字符比例切，切点吸附到比例之后最近的一个标点。两侧始终留在同一个块内，所以不会出现一条 cue 说了另一条没在说的话。

这也是按词数切会失败的原因：中文单字量约为其英文的 0.55 倍，不看比例地切，两三条 cue 之内就会飘。

## 7. 排版

中文每行 ≤ 24 字、英文每行 ≤ 44 字符，一屏最多 5 行，断点均衡且绝不落在英文单词中间。写入用 `utf-8-sig`，老播放器才不会把首行显示成乱码。

## 8. 烧录

用 `subtitles` 滤镜走 libass，微软雅黑，白字黑边，底部对齐。`-c:a copy`，音频不动。英文轨以 `mov_text` 内嵌，观众可以关掉硬字幕。

`-movflags +faststart` 把 moov 原子提前，便于边下边播。

## 9. 验收

`ffprobe` 核时长；抽五帧看有无、叠放顺序与裁切；拿一条 SRT cue 对它真实的发声点核同步；`check_srt.py` 查结构缺陷。

## 派生交付（计划中）

摘要与章节在第 6 步之后、烧录之前分叉：成对块此时已按句对齐并修正过，写摘要的人读的是证据，不是猜测。每条要点都带着它来源的 cue 时间戳；章节是同一份数据压到 12–20 个锚点，在编码时写成 ffmetadata。见[路线图](ROADMAP.md#3-摘要与章节)。

## 成本

墙钟基本被重编码吃掉，大约是实时的 1–2 倍。45 分钟 1080p 的演讲要编码 30–45 分钟——长到必须放后台跑，且超时要给够。
